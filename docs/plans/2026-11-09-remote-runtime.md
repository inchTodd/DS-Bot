# 远程运行时：Bot 在另一台机器上干活，本机只做界面

- 日期：2026-11-09
- 状态：草案，未和维护者确认；先用于讨论方向
- 相关：待开 Discussion（Ideas）；`app/src/host.mjs`、`app/src/main.mjs`、`ds-bot/src/host/browser/session.js`、`docs/plans/2026-11-04-computer-use.md`

## 为什么

- 用户在用浏览器、剪辑、Office 这类前台工具时，Bot 的电脑操控和本机资源会与用户抢同一个桌面和屏幕，用户没法同时做自己的事。
- 本机同时跑多个 Bot 时，构建、渲染和文件索引也会吃 CPU。2026-11-09 在 macOS 上实测：只要 App 里有 Bot 在 turn，GPU helper 就在 20–50%；renderer 随同时在输出的 Bot 数从约 2% 涨到 16–32%。
- App 现在只连本机 runtime：`app/src/host.mjs:70` 和 `app/src/main.mjs:274` 都写死 `127.0.0.1`。多出来的机器只能靠浏览器直接打开 `dsh web` 的界面，没有设备管理、没有边界，也没法把工具调用留在远端。
- DSH 本身已经是客户端/服务端（`dsh web`），远程 runtime 不需要改 DSH，只需要 App 侧的连接与边界。

## 已定的行为（草案，待维护者确认）

1. **设备**：用户填一次名字、URL、token，保存在 App 本地；可以保存多个，切换时重连。
2. **连接**：只接受 `https`，或 loopback、私网地址上的 `http`（选择时给出明确警告）。token 只进 App 的安全存储（keychain），不写进团队数据、不进日志。
3. **握手**：连上后校验 DSH 版本与 ds-bot 版本，不一致只提示，不自动升级、不改远端。
4. **工作目录**：连接后从远端选择工作目录；本机路径不出现在选择器里。
5. **密钥**：不随连接传输。远端用自己的 Secrets 和模型凭据；本机的 key 不会到远端。
6. **文件与附件**：上传、下载都走远端接口，显示进度与失败；不做双向同步，也不镜像本机目录。
7. **浏览器**：仍然默认 headless，每个 Bot 一个 profile；需要用户看时显示远端截图流，不接管本机浏览器。
8. **电脑操控**：远端需要时用远端桌面（noVNC 显示层）；本机不装辅助功能授权，不抢前台。
9. **断线**：本机的团队数据保持不动；重连后按 revision 恢复，不重放已经完成的 turn。
10. **信任边界**：远端 runtime 视为独立信任域，不映射本机 `DSH_HOME`，不读取本机 `~/.dsh`。

## 不做什么

- 不做自己的远程桌面协议；电脑操控仍用 DSH 的提供方。
- 不把本机文件自动同步到远端，也不把远端团队自动搬回本机。
- 不在本机保留远端 Bot 的会话副本（除非用户显式导出）。

## 分期

- **P0**：本文档 + App 里一个连接远程 URL 的实验入口（只读，不保存设备）。
- **P1**：设备管理、握手、工作目录选择、附件往返。
- **P2**：远端浏览器观看、虚拟桌面显示层。
- **P3**：多设备切换、团队迁移。

## 已知限制

- 云盒资源有限（例如 2 核 / 3.8G），十来个 Bot 并发会撑爆；需要并发上限和资源提示。
- 断线会中断正在跑的 turn，恢复策略要单独设计。
- 私网暴露：远端默认只监听 loopback，远程访问走 tailnet/VPN，不直接暴露 3080。
- 前台类操作在远端有 RTT，录制类工具可能不适合放到远端。

## 验收（草案）

- 从 App 连远端后，Bot 的工具调用发生在远端（远端进程和日志可证），同时本机 CPU 不随远端 turn 上升。
- 断开远端，App 退回本机 runtime，本机团队数据没有变化。
- 远端连接不上时，App 给出可读的错误，不静默切回本机。
